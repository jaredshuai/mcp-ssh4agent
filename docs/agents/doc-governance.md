# 持续文档治理规范 (docs/agents/doc-governance.md)

本规范规定了在 MCP SSH4Agent 项目中编写、修改、归档和治理文档的标准化操作流程，确保文档与代码实现严格同步，并防止受管生成块被非预期破坏。

---

## 1. 新文档落户与权威原则

1. **唯一事实源**：每个文档必须有明确的家，严格遵循 lazypack-discipline 固定层规范（DECISIONS.md §4，在本项目由 [AGENTS.md](../../AGENTS.md#工程纪律指针-lazypack-discipline) 与 [docs/ARTIFACTS.md](../ARTIFACTS.md) 继承约束）：
   - 术语与词汇表 -> [CONTEXT.md](../../CONTEXT.md)
   - 架构与不可逆决议 -> [docs/adr/](../adr/)
   - Agent 按需规范 -> [docs/agents/](.)
   - 用户操作手册 -> [docs/](../)
2. **禁止平行复述**：能从代码配置（如 `src/server-fields.ts`、`package.json`）推导出的事实，优先引用代码来源，不得在文档中手写硬编码冗余副本。
3. **登记与接入**：任何新增的现行文档必须同时在 [docs/README.md](../README.md)（总索引）和 [docs/ARTIFACTS.md](../ARTIFACTS.md)（产物登记册扩展区）完成登记，未登记文档视为未决草案。

---

## 2. 代码与文档同步契约

1. **执行者（Implementer）责任**：
   - 变更业务代码、CLI 命令或配置项时，必须在同一变更中同步更新受影响的文档行（例如 README、配置示例、CLI 帮助）。
   - 禁止“先提代码、随后补文档”的异步脱节做法。
2. **架构决议记录（ADR）状态准则**：
   - 仅在同时满足“难逆转、无上下文会奇怪、存在真实取舍”三项条件时，方可在 `docs/adr/` 创建新 ADR。
   - 新起草的 ADR 状态应标为 `Proposed`（待决）；只有经维护者正式采纳（或多 AI 会议裁决）后方可更新为 `Accepted`。
   - 处于实验/草案阶段的方案标为 `Draft`，严格区分“已采纳”与“已完成运行时验证”，不得在方案未落地前预填已通过。

---

## 3. 闭环角色与事件触发

根据 [docs/agents/roles.md](roles.md) 的角色分工，文档治理采用事件驱动机制：

1. **书记员（Scribe）——关票后触发**：
   - 在每个 Issue 或任务票关闭后，通读阶段性提交历史，检查全仓文档的一致性、有效性及本地 Markdown 链接。
   - 修复由于代码重构导致的过时说明或断链。
2. **清道夫（Scavenger）——发版前触发**：
   - 在执行发布流程前，扫描仓库根目录与 `docs/`，清理对应**已关闭票据且经核实可安全丢弃**的临时草稿（`.scratch/<ticket>/`）。
   - 正在进行中（In-Progress）或未关票任务的临时工作目录必须完整保留，严禁一刀切全量清空。
   - 将已被新文档完全取代的旧材料迁移至 [docs/archive/](../archive/)，并在登记册中更新为 `superseded`。

---

## 4. 归档与状态流转要求

1. **归档必须保留原文与上下文**：
   - 被废弃的说明文档使用原生文件操作移动至 `docs/archive/`。
   - 归档文件头部必须添加“历史归档标记”，明确其被替代的原因、现行替代来源（如 `README.md`）及归档背景。
   - 归档文件仅供历史溯源与背景考证参考，**不可作为当前版本的实施、配置或运行依据**。
   - 原始路径视外部引用风险保留简短跳转指针，并修复实际受影响的入站链接，防止外部书签 404。
2. **历史与决议不可抹除**：
   - ADR、CHANGELOG 与版本历史属于不可篡改的工程证据，**严禁物理删除**。
   - 当旧 ADR 被新决策取代时，旧 ADR 仅更新状态标注“已被 ADR-xxxx 取代”并附带跳转链接。
3. **未知材料审慎处理**：
   - 暂时无法确证权威来源或有效性的事项，记录于独立待核实清单中并明确证据缺口，不擅自删除，也不强行标为 `current`。

---

## 5. 托管生成块与人工目录边界

为确保自动化工具（如 `/lazypack-setup`）与人类/Agent 手工维护和谐共存，严格实行分层边界：

1. **托管生成块（Managed Blocks）保护契约**：
   - `<!-- lazypack:start ... -->` 与 `<!-- lazypack:end ... -->` 之间的内容受指纹（`fp`）与输入摘要（`input`）保护。
   - 根据 managed-blocks 契约（§5），手工修改受管块内部会导致工具检测到 DRIFT / CONFLICT，并在重新运行 setup 时触发冲突告警与中断，破坏确定性验证基线。
   - 因此，严禁在受管块内直接手工添加自定义产物登记或规则条文。
2. **人工扩展区维护**：
   - 所有全仓产物登记、自定义导航目录、历史归档索引，必须书写在 `<!-- lazypack:end -->` 标记之外的“人工维护扩展区”。
   - 入口文件（如 `docs/ARTIFACTS.md`）通过扩展区向下关联具体文档，实现自动化基准与全仓治理的解耦。
